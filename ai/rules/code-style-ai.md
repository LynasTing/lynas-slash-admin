# 代码规范

## 适用模式

当前项目处于学习模式。以下“学习模式”规则适用于新增和修改的代码；存量代码不因本规则自动要求全量重写。

项目切换为非学习模式时，使用“非学习模式”规则。切换必须由项目维护者明确说明，AI 不得自行判断。

## TypeScript

- 必须开启严格模式，禁止隐式 `any`。
- 除非需要运行时枚举 API、第三方接口约束或反向映射，否则禁止新增 `enum` / `const enum`；优先使用 `as const` 对象或数组，并推导联合类型。
- 枚举式常量集合必须使用全大写下划线命名，并以 `_MAP` 结尾；成员同样使用全大写下划线；推导出的类型使用 PascalCase。
- 普通配置对象、标签映射和局部选项使用语义化小驼峰，不得伪装为枚举常量。
- 接口请求类型必须表达 TypeScript 无法表达且影响输入、展示、序列化或调用的约束，例如长度、数值范围、日期格式和 URL 格式；对应表单或请求转换必须落实这些约束。

### 学习模式

- 局部变量默认使用 TypeScript 类型推断，避免为能够直接推断的类型重复标注；当类型不直观、初始化为空值、涉及联合类型或泛型、存在数据转换，或需要明确学习重点时，再显式标注类型。
- 导出函数、公共类型、组件 Props、接口请求与响应类型、复杂状态和复杂返回值必须显式声明类型。
- 局部函数或回调的返回类型在 TypeScript 可以直接推断、且不承担公共契约时可以省略；仅当返回值复杂、推断结果不直观、涉及递归或需要明确约束异步边界时显式声明。
- `type` / `interface` 的每个属性都必须使用多行块注释，并在中文说明后给出语义一致的英文说明；属性之间保留空行。

### 非学习模式

- 导出函数、公共类型、组件 Props、接口请求与响应类型、复杂状态和复杂返回值必须显式声明类型。
- 局部变量允许类型推导。
- 仅公共类型、接口请求与响应类型要求逐字段注释。

## 注释

### 学习模式

- 新增或修改的函数只要包含 `if`、`switch`、`map`、`filter`、`reduce`、循环、递归或嵌套结构，必须在对应逻辑前添加内部注释。
- 内部注释必须先说明中文的业务意图、数据变化或分支原因，再说明语义一致的英文内容；不得逐行翻译代码。
- TSX / JSX 片段变量必须使用多行块注释，说明片段职责和使用场景。
- 函数 JSDoc 必须先完整写中文，再空行后写完整英文；`@param` 与有实际返回值时的 `@returns` 也遵循该顺序。
- 无返回值函数的中文 JSDoc 不写 `@returns 无返回值`；英文 JSDoc 仍需写明 `@returns` 的无返回值语义。

### 非学习模式

- 仅为关键变量、核心业务逻辑、复杂状态流转、关键数据处理、性能或兼容性取舍添加注释。
- 注释说明“为什么”，不重复代码已经表达的“做什么”。

### 通用要求

- 禁止行尾注释、无意义注释、废话型注释和调试注释。
- 注释语言必须自然、简洁并符合工程语境。
- 新增或修改的注释在无需换行时，结尾不使用中文句号 `。` 或英文句号 `.`；仅当单段文本过长需要分句，或句号确实有助于表达语言结束时才使用。已存在的注释不因本规则单独修改。

## 代码结构与命名

- 当表单包含多个相互独立且输入内容较短的字段时，优先使用响应式双列布局以控制垂直长度；描述、富文本、上传等需要更大编辑空间的字段应独占整行，并在窄屏下自动回退为单列。
- 弹窗表单应建立清晰的标题与内容层级：标题字号至少高于表单正文一级，标题区与表单内容之间应保留足够的留白或使用轻量分隔线；字段、字段组与底部操作区的间距应优先保证可读性，不应为压缩弹窗高度而过度收紧。弹窗内容较多时，可适度扩大宽高，并为小视口提供滚动承载。
- 当表单中的类型、模式或类别会决定后续字段的可见性、校验或提交语义时，该控制字段必须置于表单首位，使用户先明确当前填写分支。
- 只有逻辑复杂且具备复用价值时才抽离 Hook；Hook 名称必须以 `use` 开头。
- 仅服务于单个组件、逻辑较小或抽离后增加跨文件跳转成本的状态逻辑，保留在组件内部。
- 仅使用一次且表达直白的纯函数，不得为了命名强行抽离。
- 模块职责单一，避免不必要耦合和重复代码。
- 使用语义化英文命名，禁止拼音和拼音缩写。
- 普通变量、函数和局部静态配置使用小驼峰；React 组件使用 PascalCase；文件与目录使用 kebab-case。
- 图片文件使用全小写下划线命名；图片导入变量使用 PascalCase 并以 `IMG` 结尾。
- 使用空行分隔不同职责的逻辑组。

## 质量与验证

- 代码必须完整、可运行，并优先保证可维护性。
- 禁止提交 `console.log`、`debugger`、未使用变量和未使用函数。
- 必须遵循 Prettier 与 ESLint；工具规则与本文冲突时，以工具可自动验证的格式规则为准。
- 当前可自动执行的检查：`pnpm format:check`、`pnpm lint`、`pnpm typecheck`。
- 文件命名、注释质量、学习模式中的局部变量显式类型和枚举例外理由暂未自动化；AI 在代码审查与修改完成说明中必须人工核对并报告。
- 后续强烈建议为文件命名、局部变量显式类型和新增枚举限制补充专用 ESLint 规则或检查脚本。
